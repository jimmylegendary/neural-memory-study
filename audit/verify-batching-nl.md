## Direct answers to the four targeted questions

**(a) Does self-modifying/self-referential Titans put k/v/q/learning-rate/weight-decay as test-time-updated memories?**
YES, with one caveat about q. The *fully adaptive* design (Eqs. 79–82, lines 2061–2082) makes **all** of k, v, q, η (learning rate), α (retention/forget gate), and the main memory into in-context-updated memories `M_□,t-1(·)`. The *final self-modifying* design (Eqs. 83–88) keeps **q static**: line 2116 states verbatim "𝒒𝑡 = 𝒙𝑡 𝑊𝒒 is the only non-adaptive projection, 𝜂𝑡 is the learning rate in optimization process, and 𝛼𝑡 is the retention gate (forget gate or weight decay)". So learning-rate (η) and weight-decay/forget (α) are indeed generated by their own test-time memories; query is only adaptive in the intermediate version, not the shipped one. This matches the ablation "freeze inner q" slightly *improving* ppl (12.19 vs 12.24).

**(b) Is the memory a residual 2-layer MLP M(x) = x + W1 σ(W2 x)?**
YES, verbatim. Eq. 89 (line 2158) and Eq. 91 (line 2206): `M_□(·) = (·) + W_□,1 σ(W_□,2(·))`. Text (line 2154): "the architecture of the memories are arbitrary … We use a 2-layer MLP block as the architecture of all the memories."

**(c) Is the update M_t = M_{t-1}A_t − η v̂ kᵀ, and is A_t a matrix or a scalar/diagonal gate?**
YES to the form; A_t is a **matrix** (not merely a scalar/diagonal gate). Linear dot-product case, Eq. 92 (line 2218): `M_□,t = M_□,t-1(α_t I − η_t k_t k_tᵀ) − η_t v̂_□,t k_tᵀ`. So `A_t = α_t I − η_t k_t k_tᵀ` — a full D×D data-dependent transition (scaled identity minus a rank-1 term). Note α_t *alone* is a scalar gate, but the effective transition A_t multiplying M_{t-1} is matrix-valued and data-dependent through k_t. The L2 case (Eq. 93, line 2233) keeps the same `(α_t I − η_t k_t k_tᵀ)` transition and replaces the target term with `−η_t(M k_t − v̂)k_tᵀ`. General (MLP) case Eq. 88/90 uses the same `(α_t I − η_t k_t k_tᵀ)` prefactor with a full-gradient second term.

**(d) Does "Fast and Parallelizable Training" and a chunk dual form actually appear?**
YES. §8.2 is literally titled "Fast and Parallelizable Training" (line 2162). Chunkwise scheme: split into ⌈L/C⌉ chunks, generate all k/v/v̂/η/α from the previous chunk's frozen snapshot `M_□,C×⌈t/C⌉` (Eq. 90, lines 2178–2200), and "the above updates accepts the fast parallelizable dual form that is discussed by Sun et al. (2024) and Behrouz et al. (2025c)" (lines 2210–2212). Two distinct chunk sizes are used (one for M_memory, one shared by the others; lines 2167–2170).

## Per-claim verdicts

### C2 — update form M_t = M_{t-1}A_t − η_t v̂_t k_tᵀ with A_t data-dependent matrix; batch dims M:[B,Dout,Din], k:[B,Din], v̂:[B,Dout], A:[B,Din,Din]
**CONFIRMED.** Exactly Eq. 92 (line 2218) with `A_t = α_t I − η_t k_t k_tᵀ ∈ R^{Din×Din}`, data-dependent through k_t. Dimensional bookkeeping is self-consistent: M:[Dout,Din], A:[Din,Din], v̂ kᵀ = [Dout,1][1,Din] = [Dout,Din]. Adding a leading batch axis is a mechanical extension (the analyst's own inference, not stated in the paper, but structurally valid). Minor precision note: this exact `M_{t-1}A_t − η v̂ kᵀ` closed form holds for the **linear-memory, dot-product-objective** special case; the actually-deployed memories are 2-layer MLPs whose general update is Eq. 88/90 (same A_t prefactor, but the additive term is a full `∇L` rather than the rank-1 `v̂ kᵀ`). The analyst labels it "단순화형" (simplified form), which correctly flags this.

### C3 — self-referential Titans update the memory body plus the k/v/q/lr/weight-decay-generating memory modules per context
**CONFIRMED (with a query caveat).** The fully adaptive memory (Eqs. 79–82, lines 2061–2082) makes k, v, q, η, α, and memory all in-context-updated memories with meta-learned initial states (line 2084: "the initial states of all memories, i.e., M_□,0 for any □ ∈ {k,v,q,η,α,memory} are meta-learned across all sequences/contexts"). The self-modifying step additionally has each memory generate its own value `v̂_□,t = M_□,t-1(v_t)` (Eq. 84/87). **Imprecision:** in the *final* self-modifying design q is fixed (`q_t = x_t W_q`, the only non-adaptive projection, line 2116), even though the set notation `□ ∈ {k,v,q,η,α,memory}` in Eqs. 88/90 still loosely lists q. So "query is a context-updated memory" is true only of the intermediate fully-adaptive variant, not of the shipped self-modifying/Hope model. The "per-sequence 별도 상태로 tensorize 가능" part is an analyst systems-inference (not in the paper) but is structurally sound.

### C4 — each memory module is a residual 2-layer MLP M(x)=x+W1σ(W2x); batched weights W2:[B,H,D], W1:[B,D,H]
**CONFIRMED (MLP form exact; batch tensorization is analyst-added but valid).** Eq. 89/91: `M_□(·) = (·) + W_□,1 σ(W_□,2(·))`. With hidden width H and model dim D: W_2 maps D→H ([H,D]), W_1 maps H→D ([D,H]), residual requires input=output dim D — consistent. The `[B,·,·]` batching is not asserted by the paper (it is the analyst's serving-time extension) but is dimensionally correct and is exactly the TTT-MLP batched-small-GEMM pattern the note elsewhere invokes.

### C5 — full-sequence parallelism impossible; batch axis and intra-chunk token axis parallel, chunk boundaries recurrent (M0→M1→M2); the paper's dual/chunk-wise form is this
**CONFIRMED.** Chunk-boundary recurrence with intra-chunk parallelism is exactly the §8.2 scheme: generation and inner gradients are taken w.r.t. the previous chunk's frozen snapshot so "all the gradients for the next chunk [compute] in parallel" (lines 2174–2176), yielding "the fast parallelizable dual form" (line 2211). CMS states the parallel/serial split explicitly (lines 1881–1883): "for input x_i when i ≢ 0 (mod C^(ℓ)) there is no sequential process inside the chunk and so all the computations … can be done in parallel." The cross-chunk state carry `M_□,t-1` (Eqs. 90, 92, 93) is the recurrence. Precision note: within a chunk the *state accumulation* is still a recurrence in principle; parallelism comes from the chunkwise **dual/WY-style** re-expression as matmuls (the paper cites Sun et al. 2024 / Titans for this), not from the states being independent. The analyst's phrasing "chunk 내부 token 방향은 병렬" is accurate at the level the paper claims. Batch-axis parallelism is trivially true and analyst-added.

### C6 (NL part only) — NL labels the reformulation "Fast and Parallelizable Training"; adopts chunk dual form
**CONFIRMED (NL portion).** §8.2 header "Fast and Parallelizable Training" (line 2162); NL "follow[s] the chunk-wise training algorithm of non-linear update rules (Sun et al. 2024; Behrouz et al. 2025c)" (line 2166) and inherits the "fast parallelizable dual form" (line 2211). **Scope caveat:** the *specific* mechanics C6 lists — original Titans' inner-loop mini-batch GD reformulated to "matmuls and sum" and momentum as a parallel associative scan — are stated in the **Titans paper**, not re-derived in NL. Cross-checked: Titans `2501.00663.txt` lines 414–424 ("reformulated so that it uses only matmuls and sum … split the sequence into chunks … mini-batch gradient"). NL cites this rather than restating the associative-scan/momentum details, so the "NL 명시" is accurate specifically for the *chunkwise/dual parallelizable* framing, while the matmul+sum / associative-scan derivation lives in Titans.
