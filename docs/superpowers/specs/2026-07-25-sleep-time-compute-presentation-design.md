# Sleep-Time Compute Presentation Design

- Status: proposed design; content build waits for the frozen research handoff
- Date: 2026-07-25
- Output: editable PowerPoint plus display-authoritative PDF
- Visual direction: research editorial / systems atlas
- Constraint: the deck is a generated view of evidence-controlled research,
  never a second source of scientific truth

## 1. Outcome

The presentation should look authored, not templated. Each slide makes one
claim through one dominant visual argument. It avoids the repeated rounded-card
grid, decorative generative imagery, glow/gradient/glass effects, tiny
dashboard text, stock brain/circuit/robot icons, and unreadable paper
screenshots associated with generic AI decks.

The canonical flow is:

```text
frozen presentation handoff
  → typed TypeScript scene graph
  → PptxGenJS native objects
    + Matplotlib evidence graphics
    + optional Graphviz layout coordinates
  → geometry/font/rights/accessibility gates
  → LibreOffice + Poppler diagnostic render
  → target Microsoft PowerPoint postflight
  → editable release.pptx + display-authoritative release-powerpoint.pdf
```

The research handoff owns facts, claims, citations, caveats, figure data, and
rights. The presentation renderer owns layout only.

## 2. Toolchain

| Function | Primary tool | Contract |
|---|---|---|
| authoring | TypeScript 7.0.2 + PptxGenJS 4.0.1 | native text, shapes, connectors, tables, charts, masters, notes, object names |
| scene validation | Ajv 8.20.0 | reject unknown fields, stale source IDs, and untyped visual assets |
| Korean preflight | fontkit 2.0.4 + `Intl.Segmenter("ko")` | glyph coverage, line segmentation, and measured text fit |
| OOXML inspection | JSZip 3.10.1 + fast-xml-parser 5.10.1 | relationship, media, metadata, and normalized-content checks |
| SVG fallback | `@resvg/resvg-js` 2.6.2 | deterministic real PNG fallback for every embedded SVG |
| scientific plots | Matplotlib 3.11 | SVG plus matched PNG fallback from frozen data |
| graph layout | Graphviz `plain` or JSON coordinates | layout only; redraw as native PowerPoint primitives |
| CI render | LibreOffice 24.2.7.2 + Poppler 24.02 | diagnostic PDF, images, fonts, and text extraction |
| package validation | Open XML SDK 3.5.1 in a pinned container | schema and package validation |
| PDF/UA validation | veraPDF 1.30.2 | machine accessibility gate |
| canonical final render | pinned Microsoft 365 PowerPoint desktop build | final compatibility, accessibility, and display PDF |

`python-pptx` 1.0.2 is a fallback only if a capability spike disproves the
PptxGenJS path. The existing local `slidesmith` project contributes the
content-model → render → gate pattern, not its blank-slide absolute layouts,
10–14 pt body copy, repeated cards, raster equations, or bounding-box-only QA.

### 2.1 Required capability spike

Before the first narrative slice, prove:

1. Korean, Latin, Greek, and math glyph coverage in the chosen fonts;
2. native editable mechanism diagrams and connectors;
3. editable native chart data;
4. masters/placeholders and speaker notes;
5. SVG plus real PNG fallback in Microsoft PowerPoint and LibreOffice;
6. deterministic normalized-OOXML digest;
7. PowerPoint repair-free open/save;
8. PDF font embedding and text extraction.

### 2.2 Two non-obvious caveats

PptxGenJS 4.0.1 can place `IMG_BROKEN` in a Node SVG fallback path. Every SVG
therefore ships with a PNG generated by `resvg`; a compatibility test verifies
both media parts and the rendered result.

PptxGenJS writes current dates into PPTX core properties and embedded-chart
XLSX metadata. Raw ZIP timestamps also vary. The project must not claim
byte-identical PPTX reproduction until a canonical ZIP/timestamp postprocessor
is implemented. The reproducibility identity is initially a normalized OOXML
content digest with volatile metadata excluded under a declared algorithm.

## 3. Visual system

### 3.1 Canvas and hierarchy

- 16:9 canvas and 12-column grid;
- 0.65-inch outer safe area;
- one claim and one dominant visual per slide;
- headline 30–38 pt;
- body 20–24 pt;
- 18 pt body hard floor;
- citations, axes, and legal text may use 10–14 pt;
- automatic `fit: shrink` is forbidden;
- text-fit gates retain 5–8% measured spare width/height.

### 3.2 Typography

- body: Noto Sans CJK KR;
- restrained section/display use: Noto Serif CJK KR;
- stable IDs and code: Noto Sans Mono CJK KR.

Exact upstream OTF files, OFL license text, SHA-256 digests, and
`OS/2.fsType=0` are frozen in a font manifest. The final PowerPoint postflight
uses “Embed all characters,” subject to the pinned desktop build.

### 3.3 Palette

| Token | Hex | Use |
|---|---|---|
| paper | `#F6F3EC` | primary background |
| ink | `#17191C` | main text |
| slate | `#59616A` | secondary text and structure |
| evidence cobalt | `#244E8A` | established evidence and measured paths |
| risk rust | `#9A442D` | assumptions, contradictions, and risk |
| memory teal | `#2F6B63` | memory tiers, lifecycle, and system state |

Text combinations must meet at least 4.5:1; the main palette targets 5.5:1 or
better on paper. Color is never the only encoding.

### 3.4 Narrative primitives

The deck uses a varied editorial grammar:

- chronological river for the literature lineage;
- destination × phase matrix;
- versioned memory-object state machine;
- matched-budget frontier plots;
- queue/capacity phase diagrams;
- wake/sleep/memory-cluster architecture;
- claim/counterevidence paired panels;
- one-number result slides only when the evidence gate permits a headline
  quantitative claim.

No single layout family may dominate more than three consecutive slides.

## 4. Editability contract

Every visual declares one class:

| Class | Meaning |
|---|---|
| `NATIVE` | PowerPoint text, shape, connector, table, or chart; directly editable |
| `VECTOR` | embedded SVG; sharp but not element-editable inside PowerPoint |
| `RASTER` | PNG/JPEG or licensed source figure |
| `REGENERABLE` | edit the source data/code and regenerate rather than editing in PowerPoint |

Mechanism diagrams default to `NATIVE`. Graphviz may select coordinates, but
PptxGenJS draws the final nodes and edges. Scientific plots default to
`REGENERABLE` SVG plus PNG fallback. Source-paper screenshots are exceptional
and require a positive rights record.

PptxGenJS does not provide a general native group-shape API or general
shape-level alt-text API. Generated objects receive stable names. Grouping,
reading order, and descriptions are applied only during the controlled final
PowerPoint postflight.

## 5. Citations, notes, and rights

Each slide has a short editable footer:

```text
Author et al. · Venue/Year · DOI or arXiv
```

Speaker notes contain:

- full citation;
- source and evidence IDs;
- claim ID;
- exact caveat/nonclaim;
- rights record;
- presenter interpretation clearly separated from source-reported fact.

The appendix references every source ID used in the deck.

Each visual asset has:

```text
asset_id
path
sha256
creator
source_url
license_spdx
license_evidence_url
redistribution_allowed
modified
crop
alt_text
source_ref_ids
rights_disposition
```

CC0, CC BY, public-domain, and explicitly permitted assets are the default
allowlist. An arXiv PDF or paper figure is not assumed redistributable. When
possible, the deck redraws registered data and cites it as adapted rather than
embedding a screenshot.

## 6. Automated gates

The build fails on:

- schema, reference, or digest mismatch;
- duplicate slide/object ID;
- safe-area, grid, alignment, or z-order violation;
- an unallowlisted semantic overlap;
- measured text overflow or inadequate spare room;
- contrast or color-only encoding failure;
- missing notes, citation, alt text/description handoff, or rights record;
- linked media or undeclared external relationship;
- missing SVG fallback or digest mismatch;
- invalid ZIP/OOXML package;
- unexpected PDF page count/size;
- missing embedded fonts;
- missing expected text after `pdftotext`;
- material LibreOffice versus PowerPoint render difference.

LibreOffice reports a nominal 16:9 page width near 959.981 pt rather than
exactly 960 pt; page-size validation uses a ±0.05 pt tolerance.

## 7. Human gates

1. Approve a representative 12–15 slide editorial slice before full build.
2. Review a contact sheet for pacing, hierarchy, and layout repetition.
3. Open the deck in the pinned PowerPoint build with no repair, font, or
   compatibility warning.
4. Run Korean/Latin/Greek/math torture slides.
5. Run PowerPoint Accessibility Checker and inspect reading order.
6. Move/edit/ungroup a native diagram and edit chart data.
7. Review at 1920×1080 projection size, grayscale, and common color-vision
   simulations.
8. Validate the final PDF with veraPDF and a human accessibility review.

LibreOffice’s `Tagged: yes` is not sufficient evidence of PDF/UA compliance.

```text
source/
  presentation-handoff.json
  scene-manifest.json
  theme-tokens.json

  generated-lo.pdf
  release.pptx
  release-powerpoint.pdf
  contact-sheet.png
  presenter-notes.md
  renders/
    libreoffice/
    powerpoint/
  reports/
    geometry.json
    text-fit.json
    contrast.json
    citations.json
    rights.json
    fonts.json
    ooxml.json
    relationships.json
    accessibility.json
    render-diff.json
  build-manifest.json
  checksums.sha256
```

`release.pptx` postflight may change only font embedding, grouping, reading
order, and alternative descriptions. A change to facts, chart data, copy, or
geometry invalidates the postflight and must return to the source scene.

## 9. Representative validation commands

```bash
npm ci
npm run typecheck
npm test
node dist/cli.js validate-handoff source/presentation-handoff.json
node dist/cli.js build \
  --handoff-bundle source/presentation-handoff.json \
  --output build/generated.pptx
unzip -t build/generated.pptx
```

```bash
QA_DIR=$(mktemp -d /tmp/stc-pptx-qa.XXXXXX)
soffice "-env:UserInstallation=file://$QA_DIR/profile" --headless \
  --convert-to 'pdf:impress_pdf_Export:{"UseTaggedPDF":{"type":"boolean","value":"true"},"PDFUACompliance":{"type":"boolean","value":"true"}}' \
  --outdir "$QA_DIR" build/generated.pptx
pdfinfo "$QA_DIR/generated.pdf"
pdffonts "$QA_DIR/generated.pdf"
pdftotext -bbox-layout \
  "$QA_DIR/generated.pdf" "$QA_DIR/generated.bbox.html"
pdftoppm -png -r 144 \
  "$QA_DIR/generated.pdf" "$QA_DIR/slide"
verapdf -f ua1 build/release-powerpoint.pdf
sha256sum \
  build/generated.pptx \
  build/release.pptx \
  build/release-powerpoint.pdf
```

## 10. Decisions to freeze before implementation

- canonical Microsoft PowerPoint operating system and exact build;
- venue, projector, aspect ratio, and expected viewing distance;
- whether every visual must be directly editable or whether source-regenerable
  SVG is acceptable for plots;
- language policy for slide body, figure labels, and speaker notes;
- target duration and approximate slide count.
